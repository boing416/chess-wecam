# Chess Cam — шахматы с веб-камерой

Проект из моего ролика в Instagram: как превратить обычную шахматную доску в игру против компьютера с помощью веб-камеры.

Вы двигаете настоящие фигуры, камера помогает определить ход, а Stockfish играет за соперника. Его ответ появляется стрелкой прямо на видео — фигуру за компьютер тоже переставляете вы. Интерфейс на русском, есть выбор цвета и сложности, история, отмена и экспорт партии в PGN.

**Для обычной игры языковая модель не нужна.** По умолчанию OpenCV сравнивает кадры, а python-chess проверяет допустимые ходы. LM Studio с моделью, поддерживающей изображения, можно подключить дополнительно. После установки зависимостей обычная игра работает локально, без облачных API и ключей.

Это экспериментальный DIY-проект: он отслеживает ходы от известной позиции, а распознанный ход всегда подтверждает игрок. Точность зависит от света, ракурса и неподвижности камеры.

## Что понадобится

- Обычная шахматная доска и фигуры.
- USB-веб-камера или встроенная камера и крепление, чтобы вся доска была видна сверху.
- Mac, Chrome, Git, Homebrew и Python 3.11 — эта версия Python также используется в CI.
- Stockfish и Python-зависимости: их установит `setup.sh`.

Скрипты ниже рассчитаны на macOS. Автоматическая проверка кода выполняется на Ubuntu; готовых скриптов установки для Windows и Linux в проекте пока нет.

## Запуск на macOS

Откройте Терминал и выполните:

```sh
git clone https://github.com/boing416/chess-wecam.git
cd chess-wecam
./setup.sh
./run.sh
```

Скрипт открывает [localhost:8000](http://localhost:8000) в браузере по умолчанию. Для работы с камерой откройте этот адрес в Chrome. Другой порт: `PORT=8001 ./run.sh`. Остановка сервера — Ctrl+C в Терминале.

Первичная установка требует интернета. Скрипт создаёт виртуальное окружение `.venv`, устанавливает зависимости из `requirements.txt` и при необходимости Stockfish через Homebrew. Модели он не скачивает.

## Первая партия

1. Расставьте фигуры в обычной начальной позиции. Белые занимают 1-ю и 2-ю горизонтали, белое поле h1 — справа от белых.
2. Откройте настройки камеры, выберите USB-камеру и включите её. Разрешите браузеру использовать камеру. Микрофон не запрашивается.
3. Закрепите камеру ближе к виду сверху: все 64 поля и четыре угла должны попадать в кадр, фигуры не должны перекрывать соседние поля.
4. Нажмите «Обновить кадр». Отметьте внешние углы игрового поля **a8 → h8 → h1 → a1**. Не отмечайте декоративную рамку.
5. Нажмите «Углы отмечены · запомнить расстановку». Этим вы подтверждаете, что реальная позиция соответствует стартовой позиции. По умолчанию это стандартная начальная расстановка.
6. Выберите цвет и сложность, нажмите «Начать партию». Для стандартной позиции приложение попросит по очереди нажать на видео клетки белого ферзя (**d1**) и чёрного (**d8**), у основания фигур. После проверки нажмите «Начать партию» ещё раз. Остальные фигуры сверьте со схемой самостоятельно.
7. Сделайте ход на настоящей доске. Уберите руку. Нажмите **«Я походил»**. Если играете чёрными, сначала выполните первый ход компьютера по шагу 9.
8. Проверьте распознанный ход и стрелку. Нажмите **«Да, верно»**. При ошибке нажмите «Нет», затем выберите другой предложенный вариант или нажмите «Указать ход на доске» и отметьте начальное и конечное поля на видео. Исправить ход можно и на схеме позиции. Кадр должен соответствовать исправляемому ходу.
9. Stockfish покажет ответ стрелкой. Переставьте его фигуру на настоящей доске и нажмите **«Ход компьютера выполнен»**. При рокировке переставьте также ладью; при взятии уберите захваченную фигуру.
10. Если камера не уверена в ответном ходе, приложение попросит явно сверить перестановку вручную.

Для игры мышью отключите режим физической доски в настройках перед началом партии.

## Если что-то не работает

| Проблема | Что сделать |
| --- | --- |
| Камера не включается | Откройте приложение в Chrome, разрешите доступ к камере в браузере и настройках macOS. Выберите нужную камеру в настройках приложения. |
| Ход определяется неверно | Уберите руку из кадра, проверьте свет и четыре угла доски. Камера должна оставаться неподвижной. Повторите распознавание или укажите ход вручную. |
| Проверка ферзей не проходит | Белый ферзь должен стоять на светлом поле d1, чёрный — на тёмном d8. Если фигуры стоят правильно, заново отметьте углы в порядке a8 → h8 → h1 → a1. |
| Stockfish не найден | Выполните `brew install stockfish` и перезапустите сервер. |
| Порт 8000 занят | Выполните `PORT=8001 ./run.sh` и откройте [localhost:8001](http://localhost:8001). |
| LM Studio недоступен | Для обычной игры оставьте проверку моделью выключенной. Она необязательна. |

## Отмена и продолжение

«Шаг назад» возвращает позицию до последнего хода игрока (вместе с ответом компьютера, если он уже сделан). Верните фигуры на физической доске к экранной позиции и нажмите в настройках «Фигуры как на экране · обновить опорный кадр».

Текущая партия сохраняется атомарно в `data/game.json` после каждого подтверждённого хода. При новой партии предыдущая записывается отдельным PGN в `data/`. После перезапуска сервера подключите камеру и заново подтвердите расстановку: кадры не сохраняются на диск. Кнопка PGN экспортирует партию для скачивания.

## Дополнительно: LM Studio и нестандартная позиция

Для проверки неоднозначных ходов моделью или чтения произвольной расстановки нужна локальная модель с поддержкой изображений и её vision projector. В проекте предусмотрена интеграция с Gemma 4 E4B через LM Studio. Модель и LM Studio не включены в репозиторий.

В LM Studio загрузите модель и включите локальный сервер на порту 1234. При наличии CLI:

```sh
lms server start --port 1234
lms load google/gemma-4-e4b --context-length 8192 --identifier chess-vision
```

Приложение предпочитает модель `chess-vision`. Если её нет, использует первую доступную модель, не являющуюся embedding-моделью; убедитесь, что она поддерживает изображения. Адрес ограничен `http://127.0.0.1:1234/v1`. Чтобы кадры оставались на компьютере, используйте локально загруженную модель.

Включите проверку моделью в настройках приложения, если хотите использовать её для неоднозначных кадров. Результат всё равно подтверждает игрок.

В настройках можно попросить Gemma прочитать фигуры и получить **черновик** FEN. Предпросмотр позволяет проверить каждую фигуру. Очередь хода, возможность рокировки и взятия на проходе нужно указать вручную: по одной фотографии их определить нельзя. Позиция применяется только при старте новой партии.

## Как работает распознавание и его ограничения

- OpenCV выравнивает доску по четырём углам и сравнивает кадр до хода с новым кадром.
- Изменения на полях сопоставляются с допустимыми ходами python-chess, включая рокировку и взятие на проходе.
- Если проверка моделью включена и локальное сравнение не дало уверенного результата, Gemma получает два выровненных кадра и несколько допустимых кандидатов. Она проверяет сделанный ход, а не выбирает стратегию.
- Только пользователь подтверждает запись хода; Stockfish рассчитывает ответ отдельно.
- Это отслеживание партии от подтверждённой исходной позиции, а не специализированный обученный детектор всех типов шахматных фигур. Свободное распознавание позиции через VLM экспериментальное и требует проверки.
- Низкий ракурс, блики, движущаяся камера, закрытые фигуры, несколько перестановок между кадрами и похожие фигуры снижают точность. Одно легальное перемещение за раз; при превращении пешки выберите фактически поставленную фигуру.
- Камера и модель могут ошибаться. При неоднозначном кадре предусмотрены повторное распознавание и ручное исправление, без автоматической записи хода.

## Приватность

Сервер слушает только `127.0.0.1`. Кадры поступают из браузера в локальный Python-сервер; при использовании функций модели — также в локальный LM Studio. В приложении нет внешних скриптов, CDN, аналитики и облачных API. Опорные кадры держатся только в памяти процесса. LM Studio может отдельно вести собственные журналы: их настройки контролируются в самом LM Studio.

`.gitignore` исключает кадры, партии, модели, виртуальное окружение, локальные настройки, журналы и рабочие файлы. Перед публикацией проверьте `git diff --cached --name-only` и `git diff --cached`.

## Проверка

После `./setup.sh`, при установленном Stockfish и Node.js:

```sh
.venv/bin/python -m unittest discover -s tests -v
node --check static/app.js
node tests/geometry.test.js
```

Геометрические тесты проверяют проекцию всех 64 полей в перспективе, обратное преобразование клика и разворот камеры. Видео и стрелки рисуются локально в браузере; в распознавание отправляется исходный кадр без нарисованных стрелок.

Тесты проверяют легальность, подтверждение до записи, ответы Stockfish за оба цвета, отмену, PGN, восстановление, рокировку, превращение, взятие на проходе и распознавание изменений на синтетических кадрах. Они не заменяют испытание на конкретной физической доске и камере.

## Структура проекта

| Файл | Назначение |
| --- | --- |
| `server.py` | Локальный HTTP-сервер и API приложения. |
| `game.py` | Правила, состояние партии, Stockfish и сохранение PGN. |
| `vision.py` | Выравнивание доски, сравнение кадров и необязательная проверка моделью. |
| `static/` | Интерфейс, камера, разметка и стрелки на видео. |
| `tests/` | Тесты логики партии, API, распознавания и геометрии. |
